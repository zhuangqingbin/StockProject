# 放量定义策略回测设计文档

> 日期: 2026-04-14
> 状态: Draft
> 范围: `apps/data_hub/data_pipeline_ts/analysis/`

## 1. 概述

### 1.1 目标
基于本地数据库中已有的 A 股日频行情与技术因子数据，系统性比较“放量”的不同定义在不同市场场景下的次日表现，回答两个问题：

1. 单看“放量”本身，哪些定义更有效。
2. 同一种放量定义在什么场景下更有效，例如低位、中位、高位，红盘、绿盘，以及 `MA60` 上下。

本次研究只关注“放量定义”的差异，不混入资金流、北向、融资、龙虎榜等事件驱动因子。

### 1.2 非目标

- 不做组合事件策略研究。
- 不做多周期持有收益排序，主收益口径固定为次日。
- 不直接产出实盘交易系统或自动下单逻辑。
- 不讨论成交滑点、冲击成本或涨跌停无法成交等实盘约束。

### 1.3 核心决策

| 决策项 | 选择 |
|--------|------|
| 股票池 | 全 A 股，剔除 `ST`、上市未满 60 日、停牌异常 |
| 数据来源 | 本地 MySQL，主表为 `stock_stk_factor_pro` |
| 回测收益口径 | 当日 `close_qfq` 买入，次日 `(high_qfq + low_qfq) / 2` 卖出 |
| 放量定义 | 尽量使用 `stock_stk_factor_pro` 可直接构造的量能定义 |
| 时间窗 | `2020-2022`、`2023-2024`、`2025-至今` 三段稳定性对比 |
| 排名方式 | 先过滤样本量，再按次日均收益主排序，次日胜率辅助判断 |
| 分层维度 | 长周期位置、短周期位置、红绿盘、`MA60` 上下 |

## 2. 数据与约束

### 2.1 主表

核心数据表为 `stock_stk_factor_pro`，预期使用以下字段：

- 标的与日期: `ts_code`, `trade_date`
- 价格: `close_qfq`, `high_qfq`, `low_qfq`, `close`
- 量能: `vol`, `amount`, `volume_ratio`, `turnover_rate_f`
- 趋势与位置: `ma_bfq_20`, `ma_bfq_60`, `boll_lower_bfq`, `boll_mid_bfq`, `boll_upper_bfq`
- 强弱辅助: `pct_chg`, `rsi_bfq_6`

若主表缺少横截面分位所需的现成字段，则由研究脚本按交易日临时计算，不落库。

### 2.2 股票池过滤

回测股票池统一做以下过滤：

- `ts_code` 仅保留沪深 A 股。
- 剔除名称含 `ST` 的股票。
- 上市未满 60 个交易日的股票剔除。
- 当日价格或收益关键字段缺失的记录剔除。
- 次日不存在有效 `high_qfq` / `low_qfq` 的记录不参与收益统计。

### 2.3 收益口径

信号触发日记为 `t`，收益定义为：

```text
entry_price = close_qfq[t]
exit_price  = (high_qfq[t+1] + low_qfq[t+1]) / 2
ret_next    = exit_price / entry_price - 1
```

这一定义用于研究信号强度，不代表严格可成交价格。输出中必须明确标注这一点。

## 3. 放量定义空间

### 3.1 设计原则

- 只围绕量能本身定义策略。
- 原子定义优先，避免一开始就做过深组合。
- 每个定义都要能被解释为一种常见交易语言，例如“量比放大”“换手放大”“放额”“市场横截面大额”“对个股自身异常放额”。

### 3.2 原子放量定义族

本次研究至少覆盖以下几类定义。

#### A. 量比类

- `volume_ratio >= 1.2`
- `volume_ratio >= 1.5`
- `volume_ratio >= 2.0`
- `volume_ratio >= 3.0`

#### B. 换手率类

- `turnover_rate_f >= 2`
- `turnover_rate_f >= 3`
- `turnover_rate_f >= 5`
- `turnover_rate_f >= 8`

#### C. 当日全市场成交额横截面分位

按交易日横截面对 `amount` 做分位排名：

- `amount_top30pct`
- `amount_top20pct`
- `amount_top10pct`

#### D. 个股自身成交额异常

相对个股自身历史，衡量“今天是否异常放额”：

- `amount / 20日均额 >= 1.5`
- `amount / 20日均额 >= 2.0`
- `amount >= 60日历史分位 p80`
- `amount >= 60日历史分位 p90`

#### E. 复合放量定义

用于比较“单一放量”和“多重放量同时满足”的差异：

- `volume_ratio >= 1.5 & turnover_rate_f >= 3`
- `volume_ratio >= 2.0 & turnover_rate_f >= 5`
- `volume_ratio >= 1.5 & amount_top20pct`
- `volume_ratio >= 1.5 & amount_self_p90`
- `turnover_rate_f >= 5 & amount_top20pct`
- `volume_ratio >= 1.5 & turnover_rate_f >= 3 & amount_top20pct`

最终原子策略数允许在实现阶段微调，但必须保持“量比、换手、放额、复合”四大类都被覆盖。

## 4. 场景分层定义

### 4.1 长周期位置

用近 120 交易日价格区间定义长期位置：

```text
pos120 = (close_qfq - rolling_low_120) / (rolling_high_120 - rolling_low_120)
```

分层规则：

- `低位`: `pos120 <= 0.33`
- `中位`: `0.33 < pos120 < 0.67`
- `高位`: `pos120 >= 0.67`

若区间宽度过小导致分母接近 0，则该条记录不参与该维度分层。

### 4.2 短周期位置

用布林带定义短周期位置：

```text
boll_pos = (close - boll_lower_bfq) / (boll_upper_bfq - boll_lower_bfq)
```

分层规则：

- `低位`: `boll_pos <= 0.33`
- `中位`: `0.33 < boll_pos < 0.67`
- `高位`: `boll_pos >= 0.67`

### 4.3 K 线方向

- `红盘`: `pct_chg > 0`
- `绿盘`: `pct_chg <= 0`

### 4.4 趋势位置

- `MA60上`: `close >= ma_bfq_60`
- `MA60下`: `close < ma_bfq_60`

## 5. 回测矩阵与输出

### 5.1 分析结构

输出分为三层，不做一次性暴力混排：

1. 原子放量定义总榜
2. 放量定义 × 场景分层榜
3. 分时间段稳定性榜

### 5.2 主表

#### 表 1: 原子放量定义总榜

每个放量定义输出：

- `strategy_code`
- `strategy_definition`
- `sample_count`
- `avg_ret_next`
- `median_ret_next`
- `win_rate_next`
- `std_ret_next`
- 相对全市场基准的 `excess_ret_next`

#### 表 2: 放量定义 × 场景分层榜

按以下维度分别出表：

- 长周期位置
- 短周期位置
- 红绿盘
- `MA60` 上下

每张表记录每个策略在各分层中的：

- `sample_count`
- `avg_ret_next`
- `win_rate_next`
- `excess_ret_next`

#### 表 3: 稳定性榜

每个策略在以下三段分别统计：

- `2020-2022`
- `2023-2024`
- `2025-至今`

并给出稳定性标签：

- `稳定`: 至少两段超额收益为正
- `高波动`: 仅一段显著为正，且其余阶段无一致性
- `失效`: 多数阶段不跑赢基准

### 5.3 样本量阈值

为避免样本过小导致排名失真，统一采用以下阈值：

- 主榜: `sample_count < 500` 不进入主排名
- 分层榜: 单格 `sample_count < 50` 不展示
- 稳定性榜: 单时间段 `sample_count < 100` 标记为“不稳定样本”

## 6. 排名与解释规则

### 6.1 排名规则

排序逻辑固定为：

1. 先做样本量过滤
2. 按 `avg_ret_next` 降序
3. 按 `win_rate_next` 降序辅助排序

### 6.2 输出解释

最终结论不只给“冠军策略”，而要回答：

- 哪种放量定义本身最有效。
- 哪种放量定义只在低位有效。
- 哪种放量定义在红盘确认时有效。
- 哪种放量定义在 `MA60` 下方失效。
- 哪些定义具备跨市场阶段稳定性。

## 7. 实现方案

### 7.1 推荐实现路径

在 `apps/data_hub/data_pipeline_ts/analysis/` 下新增独立研究脚本或模块，避免污染已有单表分析。

推荐结构：

```text
analysis/
  volume_definition/
    analyze.py
    output/
      strategy_summary.csv
      by_pos120.csv
      by_boll_pos.csv
      by_candle_color.csv
      by_ma60_side.csv
      stability_summary.csv
```

### 7.2 数据处理流程

1. 读取主表所需字段。
2. 基于 `ts_code, trade_date` 排序。
3. 计算次日 `(high_qfq + low_qfq) / 2` 收益。
4. 计算长期位置、短周期位置、成交额横截面分位、自身历史放额指标。
5. 生成原子放量定义布尔列。
6. 按总榜、分层、稳定性分别聚合。
7. 输出 CSV 与终端摘要。

### 7.3 错误处理

- 若某一策略在某段样本不足，输出 `sample_count` 和空排名，不抛异常。
- 若某交易日横截面分位无法计算，跳过该日对应横截面定义。
- 若某标的历史长度不足，仍可参与不依赖长窗口的策略，但不得参与需要该窗口的定义。

## 8. 验证与测试

### 8.1 结果校验

- 抽样核对若干标的的 `ret_next` 计算是否与 SQL 明细一致。
- 抽样核对 `pos120`、`boll_pos` 的分层边界是否正确。
- 验证所有主榜策略样本数均大于等于阈值。
- 验证稳定性标签与分段结果一致。

### 8.2 回归测试

新增测试至少覆盖：

- 收益口径计算函数
- 长周期位置与短周期位置分层函数
- 成交额横截面分位计算
- 样本量阈值过滤和稳定性标签逻辑

## 9. 风险与边界

- 次日 `(高+低)/2` 是研究口径，不是可成交价，可能高估部分策略表现。
- 成交额绝对值跨年份不可直接比较，因此只作为分位或相对值使用。
- 位置分层与 `MA60` 上下存在相关性，但两者分别代表“区间位置”和“趋势位置”，保留两套分层是有意设计。
- 放量定义过多时容易产生数据窥探偏差，因此输出中必须保留样本量和分段稳定性，不能只看单一时期收益冠军。

## 10. 交付物

本次设计对应的最终交付物为：

- 研究脚本或模块
- 6 张以内的结果 CSV
- 一份终端摘要，包含总榜、分层结论和稳定性结论
- 必要的单元测试
