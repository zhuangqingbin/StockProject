回测引擎执行流程

单次回测的完整生命周期
① 接收请求
FastAPI Router
→
验证参数 → 创建 backtest_runs 记录 (status=pending) → 返回 run_id
② 提交进程池
ProcessPoolExecutor
→
submit(run_backtest, run_id, config) → status=running → 返回 Future
③ 子进程执行
run_backtest()
→
以下全在子进程中执行 ↓
3a 加载策略代码 — strategy_loader 动态导入, 校验继承自 bt.Strategy
3b 准备数据 — data_registry 查找所需 Plugin → query MySQL → DataFrame → bt.feeds
3c 配置 Cerebro — 添加 DataFeed, Strategy, Broker (cash, commission), Analyzer, Observer
3d 执行回测 — cerebro.run(), 通过回调更新进度到共享队列
3e 提取结果 — result_extractor 解析交易记录、每日净值、Analyzer 输出
④ 结果持久化
result_extractor
→
写入 backtest_trades + backtest_daily → 计算 metrics → 更新 backtest_runs (status=completed)
⑤ 通知前端
WebSocket
→
Future 回调 → WebSocket 推送完成事件 → 前端自动刷新结果

进度推送机制

子进程 → 主进程
使用 multiprocessing.Queue
子进程在 Backtrader 的 next() 回调中
按固定间隔 (每处理 N 个 bar) 写入进度
queue.put({"run_id": 1, "progress": 67})
主进程 → 前端
后台 asyncio task 轮询 Queue
通过 WebSocket 推送给订阅的客户端
同时更新 DB 中的 progress 字段
ws.send({"type": "progress", "run_id": 1, ...})

策略代码安全执行

安全边界设计 (小团队场景)
代码加载
  • 动态 import，非 exec/eval
  • 校验必须继承 bt.Strategy
  • 校验必须实现 next() 方法
资源限制
  • 超时控制 (默认 5 分钟)
  • 子进程隔离，崩溃不影响主服务
  • 最大并发任务数限制
信任模型
  • 小团队 = 信任用户代码
  • 不做沙箱 (过度工程化)
  • 通过代码审查保障安全
