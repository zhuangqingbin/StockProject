# data_explorer Page Specification

> Date: 2026-03-17
> Status: Ready for implementation planning
> Based on: `prd.md`

## 1. Purpose

本文档把 `prd.md` 中已经确认的需求拆成页面级说明，明确每个页面的模块组成、默认状态、关键交互和展示口径，供后续实现计划直接引用。

## 2. Global Rules

### 2.1 Shared Navigation

- 平台默认进入目录页
- 顶部导航至少包含：
  - 数据目录
  - 运维监控
  - Database Metadata
- 左侧导航树用于业务分类浏览
- 左侧分类节点显示表数量

### 2.2 Shared Terminology

- 分类：`basic_data`、`financial_data` 等业务分组
- 表状态：`延迟`、`无数据`、`异常`、`正常`、`手工维护`
- 最近更新时间：平台可见的最近一次成功更新时点
- 最新数据日期：表内最新业务日期

### 2.3 Shared UI Priorities

- 先展示结构和状态，再展示数据值
- 数据展示坚持只读
- 所有默认排序和默认入口必须固定，不要求用户先配置

## 3. Directory Page

## 3.1 Goal

帮助用户按业务分类找到表，并快速判断是否值得点进去。

## 3.2 Layout

- 左侧：分类树
- 右侧：当前分类表列表
- 顶部：当前分类标题、搜索框、可选状态筛选

## 3.3 Default State

- 默认落到首个有效分类或上次访问分类
- 右侧只显示当前分类下的全部表
- 默认搜索为空
- 默认按“状态优先 + 最近更新时间倒序”排序

## 3.4 Table List Columns

右侧表列表默认字段：

- 表名
- 中文说明
- 总行数（精确值）
- 最新数据日期
- 最近更新时间
- 状态

## 3.5 Interactions

- 点击左侧分类：刷新右侧为该分类表列表
- 在搜索框输入关键字：只过滤当前分类结果
- 点击表行：进入该表详情页
- 点击排序列：允许临时排序，但离开页面后仍回到默认排序规则

## 3.6 Empty And Error States

- 当前分类无表：显示“当前分类暂无可展示表”
- 搜索无结果：显示“当前分类下无匹配结果”
- 表统计获取失败：保留表名和分类，统计字段显示获取失败状态

## 4. Table Detail Page

## 4.1 Goal

帮助用户从单表层面理解“这是什么表、结构是什么、状态如何、数据长什么样”。

## 4.2 Layout

- 顶部：表摘要区
- 中间：结构信息区
- 下方或次级 tab：数据预览区

## 4.3 Default State

- 默认先展示结构信息
- 数据预览不作为首屏
- `建表 SQL` 默认折叠

## 4.4 Summary Area

摘要区展示：

- 表名
- 中文说明
- 所属分类
- 来源系统
- 关联 job
- trigger profile
- 总行数
- 最新数据日期
- 最近更新时间
- 状态

## 4.5 Structure Area

结构区至少包含四个模块：

1. 字段列表
   - 字段名
   - 类型
   - 默认值
   - 可空
   - 注释

2. 索引信息
   - 主键
   - 唯一键
   - 普通索引

3. 约束信息
   - 约束名
   - 约束类型
   - 关联字段

4. DDL 区
   - 建表 SQL
   - 默认折叠

## 4.6 Interactions

- 点击预览 tab：切换到数据预览区
- 点击 DDL 折叠面板：展开完整建表 SQL
- 点击字段名：允许后续扩展字段说明，不要求首期支持复杂联动

## 5. Data Preview

## 5.1 Goal

让用户在不离开平台的情况下对任意纳入范围表做只读浏览。

## 5.2 Scope

- 所有纳入范围的表都必须支持
- 预览必须是全字段，不裁剪列

## 5.3 Default State

- 默认每页 50 行
- 默认按主日期列倒序
- 无日期列时回退到主键或第一索引排序

## 5.4 Interactions

- 分页浏览整张表
- 按主日期列筛选
- 按 `ts_code` 筛选
- 临时排序当前页结果

## 5.5 Constraints

- 只读
- 不支持写入
- 不支持任意 SQL
- 不支持导出

## 5.6 Empty And Error States

- 表存在但无数据：显示空表提示
- 预览加载失败：显示错误占位并保留返回结构区能力

## 6. Monitor Page

## 6.1 Goal

让用户快速判断平台数据是否健康、哪些任务失败、哪些表延迟。

## 6.2 Layout

监控页使用两个并列 tab：

- 表视角
- 任务视角

## 6.3 Default State

- 默认先落到表视角

## 6.4 Table Perspective

表视角重点字段：

- 表名
- 所属分类
- 最新数据日期
- 最近更新时间
- 状态
- 是否延迟

默认用途：

- 快速发现延迟表
- 快速发现无数据表
- 快速发现状态异常表

## 6.5 Task Perspective

任务视角重点字段：

- job 名
- 关联表
- 最近执行状态
- 执行时间
- 耗时
- 错误信息

默认用途：

- 查看失败任务
- 查看异常任务
- 排查延迟来源

## 6.6 Shared Interactions

- 支持按状态筛选
- 支持只看失败 / 只看延迟 / 只看无数据
- 支持从任务跳到表详情
- 支持从表状态跳到表详情

## 7. Database Metadata Page

## 7.1 Goal

让用户从数据库整体层面查看结构信息，而不是只停留在单表视角。

## 7.2 Default Landing View

默认先展示库级概览。

## 7.3 Overview Modules

概览页建议包含：

- schema 名称
- 表总数
- 分类分布
- 系统表数量
- 数据库结构入口卡片

## 7.4 Detail Modules

从概览页可继续进入：

- DDL 列表
- 索引列表
- 主键与约束列表
- 字段元信息列表

## 7.5 Interactions

- 点击结构入口卡片：进入对应明细页
- 点击某张表：跳回该表详情页

## 8. States And Feedback

## 8.1 Loading

- 页面首屏加载必须有明显 loading 态
- 列表区和详情区可分别加载，避免整页阻塞

## 8.2 Empty

- 无表
- 无数据
- 无索引
- 无约束

以上空态都应给出明确说明，不显示空白页。

## 8.3 Error

- 查询失败
- 统计失败
- 元信息加载失败

错误信息需要清楚说明失败的是哪一块，不要只给通用报错。

## 9. Page-To-Page Flow

主要路径如下：

1. 目录页
   - 选择分类
   - 查看当前分类表列表
   - 进入单表详情

2. 单表详情
   - 先看结构
   - 再切到数据预览

3. 监控页
   - 先看表视角
   - 再切任务视角
   - 从异常项跳到单表详情

4. Database Metadata
   - 先看库级概览
   - 再看结构明细
   - 再跳转到具体表详情
